## What changed
The protocol now treats every spec as the living source of truth for its feature - the backbone
of AI-driven development that agents read to know what a feature *is*. Two rules make that real:

- **Route first, write second.** Before writing a spec, decide **net-new vs. a change to an
  existing spec**. If a spec already owns the behavior, revise it in place instead of adding a
  second spec that contradicts the first.
- **Keep specs accurate as the system evolves.** When behavior changes - a new requirement, a
  dropped scope item, a different approach - update the owning spec in the same PR so the spec
  and the shipped software never disagree.

A stale spec misleads every later change, so revising a spec is now the norm, not the exception.
